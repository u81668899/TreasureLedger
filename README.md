# 挖宝会计 · 卫月版

FFXIV 卫月（Dalamud）插件：宝物库挖宝的掉落统计、账本与自动投掷。

从 ACT 的 Triggernometry 触发器脚本迁移而来，参考脚本保存在 [`reference/`](reference/)。

> **本插件由 DeepSeek 从零编写，无任何人工编码含量。**
> 全部代码、架构设计、UI 布局、调试与迭代均由 DeepSeek 完成，
> 人类使用者只提出需求、反馈问题并做验收。

---

## 功能

### 统计

- **掉落统计**：按宝图类型分类累计，覆盖 G1-G8 / G10 / G12 / G14-G15 / 深层绿 / G17-G18，共 68 项内置物品
- **三种来源分离计数**：小怪掉落、宝箱开启、投掷分配
- **投掷去重**：投掷通知与进包分开处理，按件排队兑现，支持同一物品多件同时投掷
- **物品开关**：默认全部统计，可逐项关闭
- **自定义显示名**：每件物品可改播报用的短名，留空则用游戏原名
- **自增物品**：版本更新后玩家可自己补充，不必等插件更新；支持按物品名或 ID 添加

### 计数

- **洞数**：每次进入宝库 +1
- **地图数**：陷阱魔物全清 +1
- **底数**：下底 boss 判定（boss 名唯一，规避掉线日志重叠）
- **层数**：进本先记 0 层，魔纹/大门推进 +1，运河 X区 与宝库 X层 统一记录
- **神殿分级**：G10/G12/G15 用上中下级，G17-G18 用大梦终梦
- **开箱计数**：直接读宝箱对象，不靠金币数猜测

### 播报

- **聊天栏指令**：默认 `/挖宝查询`、`/挖宝重置`，均可改名
- **正则支持**：指令可切换正则匹配，语法正确显示绿底，错误显示红底
- **谁发的就回谁**：默语 / 小队 / 本服贝 / 跨服贝 / 悄悄话
- **多贝支持**：通讯贝可多选，同时挂在多个贝里都会各回一份
- **招募内容**：三路数据源，只记录自己进的那支队伍
- **进队重置**：加入小队、开招募时自动清零

### 自动投掷

- 参考 LazyLoot 的成熟实现，特征码定位游戏投掷函数
- 默认关闭，关闭时完全不触碰游戏
- 挖宝场景判定：宝库副本内 + 野外打宝图怪期间
- 白名单 / 黑名单两种模式，每件物品可单独指定策略
- 需求 / 贪婪 / 放弃，三种投掷方式

### 传送提醒与自动确认

- **传送提醒**：收到传送邀请时在聊天栏提示
- **自动确认**：检测到是传送邀请时自动点「是」
- **场景限制**：默认只在「挖宝队伍」中生效，防止误确认其他邀请

挖宝队伍判定（照搬 Triggernometry XML「2.0招募进组重置」），三条件同时满足：

1. 通过招募加入的（不是随便组队）
2. 当前仍在队伍中
3. 那支招募被判定为寻宝招募

寻宝招募的判定规则：

| 招募标题 / 简介 | 判定 |
|---|---|
| 标题以「寻宝」开头 | ✅ 是 |
| 标题为「讨伐歼灭战：那布里亚勒斯讨伐战」 | ✅ 是（挖宝队常用） |
| 标题以「讨伐歼灭战：」开头，简介含挖宝特征 | ✅ 是 |
| 其他标题，简介含挖宝特征 | ✅ 是 |
| 都不匹配 | ❌ 否 |

挖宝特征正则：`((G|g)\d{1,2}|深绿|绿图)` 后跟张数，如「G18 12张图」「深绿 5t」

实现基于 FFXIVClientStructs 的 `AtkUnitBase.FireCallbackInt`：
监听 `SelectYesno` 出现 → 读提示文本 → 匹配传送关键词 → `FireCallbackInt(0)` 点「是」。
不依赖 YesAlready 等第三方插件。

### 小怪记录与标记

- **小怪记录**：顺序怪 / 金币怪 / 战斗怪，出现→消失时已死=击杀、未死=逃走
- **顺序怪标记**：洋葱→攻击1、茄子→2、蒜头→3、番茄→4、王后→5
- **金币怪标记**：按出现顺序轮转攻击 1-5
- **神殿标点**：进本自动放十字四点 A/B/C/D，坐标取自 XML
- 全部为**本地标记**，只有自己可见，队友看不到

小怪名单全部来自 Triggernometry XML，一个不多一个不少：

| 类别 | 名单 |
|---|---|
| 顺序怪 | 运河/神殿/宝库/神秘/惊奇/育体/图拉尔/金库 + 洋葱·茄子·蒜头·番茄·王后（育体大蒜为特例写法） |
| 金币怪 | 哥布林寻宝猎人、鲶鱼精盗贼、金鲶、水妖魔术师、黄金协助机、育体拉姆帕斯、财富羊驼、黄金猫 |
| 战斗怪 | 阿尔戈斯、艾卜哈拉木、神殿象魔、宝库守护者、七彩巨像、育体吕萨、财富呜噜怪、金库守卫 |

### 长期存储

- 按「月」分卷，避免单文件过大
- 查询只打开命中的分卷，不加载全部历史
- 统计表格支持：24小时 / 今天 / 3天 / 本周 / 本月 / 本季度 / 半年 / 今年 / 全部
- 两种视图：按行程（逐次明细）、按时间段（按天/按周聚合）

## 安装

1. 游戏内 `/xlplugins` → 开发插件 → 添加
2. 目录指向编译输出的 `TreasureLedger.dll`
3. 或直接把 `TreasureLedger.dll` + `TreasureLedger.json` 放进 `%APPDATA%\XIVLauncherCN\devPlugins\TreasureLedger\`

需要 .NET 10 SDK 与 `Dalamud.NET.Sdk/15.0.0`。

cd src/TreasureLedger

## 技术说明

### 掉落数据来源

掉落直接从游戏的 `LogMessage` 事件取，不解析聊天文本，参数里就是 ItemId：

| LogMessageId | 含义 | 参数 |
|---|---|---|
| 1232 | 获得了"物品" | `[0]` ItemId |
| 1233 | 获得了"物品"×N | `[0]` ItemId, `[1]` 数量 |
| 1254 | 获得了新的战利品（投掷） | `[0]` ItemId, `[1]` 数量 |
| 1258 | 获得了 N 金币 | `[0]` 金额 |
| 2165 | 获得了 N 个神典石 | `[0]` 数量 |

参数类型为 `SeStringParameter`，`UIntValue` 直接就是 ItemId / 数量。

### 副本判定

用 `ClientState.TerritoryType` 判定。编号与 ACT 通用，已实测 1279 = 巡梦金库、1192 = 加加财富天坑。

### 宝箱

`FFXIVClientStructs.FFXIV.Client.Game.Object.Treasure` 对象可直接读取：
- `State`：宝箱状态
- `_lootableItemIds`：16 个可拾取物品 ID

这是 ACT 做不到的，也是自动退出功能的基础。

### 退出副本

调用 FFXIVClientStructs 的 `GameMain.ExecuteCommand(819, ...)`，
819 = `ExecuteCommandFlag.LeaveDuty`。这一行就能退本，不需要打开任何 UI。

实现思路来自 DailyRoutines 的 `LeaveDutyCommand`，但**不依赖该插件** ——
最终落点是 Dalamud 自带的 FFXIVClientStructs。

**维护与容错**：该函数由 CS 通过特征码
`E8 ?? ?? ?? ?? 66 41 89 B7 ?? ?? ?? ?? ?? ?? ??` 定位。
游戏大版本更新而 CS 尚未跟随时，特征码会失配、地址归零，直接调用会崩溃。
所以插件启动时会用同一特征码做**预检**：
- 预检通过 → 允许调用
- 预检失败 → 禁用退本功能并在 UI 提示，绝不冒险调用

### 自动投掷

参考 [LazyLoot](https://github.com/NiGuangOwO/LazyLoot)（MIT）的反编译实现：

```
delegate bool RollItemRaw(Loot* loot, RollChoice option, uint index);
特征码 "41 83 F8 ?? 0F 83 ?? ?? ?? ?? 48 89 5C 24 08"
```

可投掷判定照抄其过滤条件（非宝箱来源、已投过、状态不可投、模式排除、空槽）。

**为什么这里不能像退本那样用 CS**：已确认 FFXIVClientStructs 的 `Loot` 类
只有 `Instance` / `ReceiveEvent` / `ReceiveEventWithResult` / `get_Items`，
没有投掷入口，`ReceiveEvent` 是 Atk UI 事件，语义不对。所以只能沿用特征码方案。

**维护与容错**（向 CS 维护模式靠拢）：
- 启动时用同一特征码做**预检**，失败则禁用自动投掷，绝不调用空指针
- 支持**自定义特征码覆盖**：游戏更新后若内置特征码失效，
  可在插件面板「自动投掷 → 高级：自定义特征码」填入社区新特征码，不必等更新
- 支持**多候选特征码**，按顺序尝试

## 风险与注意事项

- **自动投掷会真的操作游戏**，请先在安全场景（比如野外小怪）测试，确认行为正常再用到宝库
- 自动投掷**默认关闭**，关闭时不执行任何写操作
- 关键判定依赖游戏版本的特征码与结构偏移，**游戏大版本更新后可能需要跟进调整**
- 插件已在退本与自动投掷处加入特征码预检：解析失败只会禁用对应功能，不会导致游戏崩溃
